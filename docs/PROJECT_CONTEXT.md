# 项目上下文

## 目标

把指定 Discord 美股波段频道的消息完整留档，解析成可审查的候选交易指令，结合实时行情做有限资金的前向模拟交易，并在网页展示持仓、资金利用率、信号延迟、滑点与收益复盘。

## 当前边界

- 当前是个人使用的模拟交易工作台，不连接真实券商，不自动下真实订单。
- GitHub Pages 网址是脱敏静态演示；本机动态后端负责 Discord、数据库、长桥和逐笔明细。若要跨设备长期在线，仍需要独立后端服务器。
- 本机 PostgreSQL 13.21 已创建项目数据库 `swing_signal_desk`、最小权限应用角色和 Navicat 只读角色；密码不得写入仓库或聊天。
- 本地 `.env` 已设置 `DATABASE_URL`，后端默认使用 PostgreSQL。移除该值才会回退到重启即清空的内存演示模式。
- 已回补目标频道最近一个月 629 条原始消息，并生成可审计的信号级交易腿；严格自动统计与组合模拟收益必须保持分离。
- 本地网页通过后端显示真实月度聚合与原文；公开 GitHub Pages 只显示隐私降级状态，不嵌入付费频道内容。
- 长桥只读报价已接入网页行情卡，必须展示盘前/盘后或常规盘标签及时间；不得用当前行情改写历史成交价。
- 已完成 `finite-capital-v1` 历史账户回放：100 万美元起始资金、70% 总仓上限、12% 单标的上限、常规仓六批、每边 10 bps 滑点和 2 bps 费用。
- 最新回放写入独立的版本化表，不覆盖信号腿；网页把账户增长率、严格胜率和当前浮盈分开显示。
- 回放同时保存理想、基础和延迟压力三套成交成本情景；网页单列卖单匹配率与持仓报价覆盖率，不把覆盖率、胜率和收益混成一个分数。
- 本机版允许导出完整回放流水 CSV；公开 Pages 不嵌入逐笔、持仓或付费频道原文。
- 页面以“全部数据”为总览，以滚动近 7 天、近 30 天为子周期；所有周期都锚定最新已采集消息，信号统计与账户回放使用同一数据截止时点。
- Discord Gateway 在线时即时写入；服务器每 60 秒主动补扫，页面首次打开也会请求补扫（30 秒节流），界面通过 SSE 即时更新并以 30 秒轮询兜底。
- 新的严格策略腿写入后以约 5 秒防抖合并触发新回放版本；模糊消息仍只进入待复核，不自动模拟成交。
- Windows 登录启动任务只启动本机服务，不把 Token 或数据库密码复制到任务计划；密钥继续只从被 Git 忽略的 `.env` 读取。
- 本机版支持 PWA，并在桌面安装直接指向 Edge/Chrome 独立窗口的“波段信号台”快捷方式；后端由 Windows 登录任务自启，`npm run desktop:open` 作为健康检查与隐藏启动备用入口。
- 桌面宽度下左侧导航固定并随滚动高亮；窄屏时转换为顶部固定横向导航，长页面另有回到顶部按钮。

## 核心决策

1. Discord 只允许官方 Bot；保留 create/update/delete 原始事件。
2. 确定性规则优先，AI 仅在规则不够明确时给候选结果。
3. AI 必须返回 JSON Schema 约束的结构；输出仍视为不可信输入。
4. 所有候选先经过资金与风险规则；即使通过，也只允许人工确认后的模拟成交。
5. 收益同时记录信号价与模拟成交价，不把理论最高收益当成可执行收益。
6. 所有关键行为写审计记录，规则、解析器和模型必须带版本。

## 默认风控

- 初始资金：1,000,000 USD
- 总资金利用率上限：70%
- 单一股票权重上限：20%
- 强制现金垫：30%
- 规则解析置信度阈值：85%
- 信号最大允许时延：120 秒

这些是可配置默认值，不代表投资建议。改动时必须记录生效时间和版本。

历史账户回放为了更谨慎地学习频道分批操作，单独采用 **12% 单标的上限**；它不会改写通用风险引擎的 20% 默认值。

## 下一次继续工作的入口

1. 先阅读根目录 `AGENTS.md` 和本文件。
2. 查看 `docs/CHANGELOG.md` 的最后一条和 `docs/ROADMAP.md` 未完成项。
3. 运行 `npm ci`、`npm test`。
4. 检查 `git status` 和两个远端，避免覆盖用户修改。
5. 数据库变更从 `db/migrations/` 追加新迁移，禁止重写已经上线的迁移。
6. 运行 `npm run db:verify`，确认应用角色非超级用户、迁移完整、Navicat 角色只读。
7. 需要刷新历史账户估值时运行 `npm run db:replay`；该命令会追加一个新回放版本并读取长桥当前价，不会覆盖旧回放。
